# Проект сайта АКВТ (Астраханский колледж вычислительной техники)

Структура репозитория:

* **`/site`** — Основной публичный сайт колледжа (статическая сборка, адаптивная вёрстка, стили, медиатека, расписание).
* **`/admin`** — Панель управления контентом колледжа (Admin Control Hub) для редактирования специальностей, преподавателей, документов, расписания и глобальных настроек.
* **`/wordpress`** — Официальная тема `akvt-theme` и плагин ядра `akvt-core` для интеграции с WordPress.

## Режим «Версия для слабовидящих»

Файлы режима (в `site/` и копии в теме WordPress `assets/`):

| Файл | Назначение |
| --- | --- |
| `js/vision.js` | Состояние (localStorage), панель настроек, кнопка-«глаз», озвучивание, классы на `<html>` |
| `css/vision.css` | Цветовые схемы, размер текста, интервалы, изображения, интерфейс панели |
| `css/vision-layout.css` | **Генерируется.** Адаптивные `@media`-правила сайта под «эффективную ширину» |

**Новая страница.** Перед `</head>` (после `style.css` и `adaptive.css`) нужны три строки
(пути — от глубины страницы), никакой разметки в `<body>` не требуется:

```html
<link rel="stylesheet" href="css/vision-layout.css" />
<link rel="stylesheet" href="css/vision.css" />
<script src="js/vision.js"></script>   <!-- без defer: класс режима ставится до первой отрисовки -->
```

Для уже существующих страниц есть идемпотентный скрипт: `python3 site/tools/patch-pages-vision.py`.

**После правок адаптивного CSS** (`adaptive.css`, `@media` в `style.css` и страничных CSS)
перегенерируйте слой раскладки: `cd site && python3 tools/build-vision-layout.py`
(и скопируйте `vision-layout.css` в `wordpress/.../akvt-theme/assets/css/`).


## Как посмотреть изменения до публикации (предварительный просмотр)

Любая правка сначала попадает в отдельную ветку и Pull Request. Основной сайт при этом **не меняется**,
пока кто-то не нажмёт «Merge pull request».

### Способ 1. Превью от Vercel (проще всего, ничего не нужно устанавливать)

1. Откройте Pull Request на GitHub (вкладка **Pull requests** → нужный запрос).
2. Прокрутите страницу вниз до блока проверок. Там будет строка **Vercel** со ссылкой **Visit Preview**
   (или комментарий бота Vercel с кнопкой **Visit Preview**).
3. Откройте ссылку: это точная копия сайта с изменениями на отдельном адресе. Ссылка живёт отдельно
   от основного сайта, ей можно поделиться, чтобы показать результат коллегам.
4. После нового коммита в ту же ветку превью обновляется само, через 1–2 минуты.
5. Проверьте на телефоне: откройте ссылку превью в браузере телефона.

Если строки Vercel нет: подождите минуту (идёт сборка) или откройте панель Vercel → проект → **Deployments**,
там у каждой ветки свой адрес.

### Способ 2. Быстрая проверка адаптивности в браузере компьютера

1. Откройте превью (или сайт) в Chrome или Edge, нажмите **F12**.
2. Включите режим устройств (значок телефона и планшета, или **Ctrl+Shift+M**).
3. Выберите телефон (например, 360 или 390 px) и планшет (768 px), перезагрузите страницу.
4. Включите «Версию для слабовидящих» (кнопка-глаз справа внизу) и пройдите те же размеры:
   текст не должен обрезаться, горизонтальной прокрутки быть не должно, меню должно открываться и прокручиваться.
5. После выхода обновления нажмите **Ctrl+F5**, чтобы сбросить кэш браузера.

### Способ 3. Запуск на своём компьютере

Нужен только Python. В папке проекта:

```bash
git checkout feature/имя-ветки
cd site
python3 -m http.server 8765
```

Откройте в браузере `http://127.0.0.1:8765/`. Для карт и шрифтов с внешних сайтов нужен интернет.
Расписание занятий читает файлы `.xls` из `site/wp-content/uploads/2026/09/`.

### Как откатить

В Pull Request, который уже влит, есть кнопка **Revert**: GitHub создаст новый запрос, отменяющий изменения.
Быстрый вариант: в Vercel → **Deployments** выбрать прошлое развёртывание → **Promote to Production**.

## Как можно улучшить сайт

Список ниже отсортирован по пользе для посетителей. Первые пункты дешёвые и быстрые.

### Быстрые улучшения

- **Расписание занятий.** Сейчас имена файлов расписания записаны в код страницы. Вынести их в один
  настраиваемый список или подхватывать новые файлы автоматически, чтобы учебной части не нужна была
  правка кода каждую неделю.
- **Карта общежития.** Сейчас это картинка с водяным знаком «API KEY REQUIRED». Заменить на интерактивную
  карту (как «Схема проезда») или на чистый снимок, адрес вывести крупным текстом.
- **Оформление документации (раздел «Преподавателям»).** Плитка ведёт на главную страницу. Указать правильную страницу.
- **Ключ Яндекс Карт** лежит прямо в странице. Ограничить его по домену в кабинете Яндекса.
- **Картинки.** Прогнать изображения через сжатие и добавить `width`/`height` и `loading="lazy"`: страницы
  станут быстрее открываться на мобильном интернете.
- **Подписи `alt`** у всех картинок: сейчас у части картинок стоят названия вроде «01», «02».

### Админ-панель

- Сейчас панель (`/admin`) хранит данные только в браузере, а посетители сайта изменений не видят.
  Нужны: сервер или база данных (или запись изменений в репозиторий), вход по логину и паролю,
  роли и журнал действий. Всё это уже есть в WordPress-плагине `akvt-core` и заложено в новой CMS
  (`akvt-cms`, Laravel + Filament).
- Связать галочку «кнопка для слабовидящих» в настройках подвала с сайтом или убрать её.
- Пересобрать архивы `admin/*.zip` (тема и плагин): они собраны до режима для слабовидящих.

### Версия для слабовидящих

- Проверить на реальных телефонах (iOS Safari, Android Chrome) и со встроенными программами чтения с экрана
  (NVDA, VoiceOver, TalkBack): автоматические тесты это не заменяют.
- Добавить режим «только текст» (без декоративных блоков) и запоминание размера шрифта отдельно для телефона.
- Подключить проверку доступности (axe или Lighthouse) к проверкам перед слиянием.

### Общее качество сайта

- **Автоматические проверки перед публикацией.** Подключить в GitHub проверку (GitHub Actions): ссылки не
  битые, на страницах нет горизонтальной прокрутки на 360 и 768 px, у страниц есть заголовок и описание.
- **Единый шаблон шапки и подвала.** Сейчас они вставлены в каждый из примерно 290 файлов; правка шапки
  делается скриптом. Перейти на шаблонизатор или на новую CMS, чтобы правка делалась в одном месте.
- **Кэш PWA.** Стили и скрипты теперь берутся из сети, но при выходе новых версий стоит также повышать
  номер кэша `CACHE_NAME` в `sw.js`.
- **Поиск по сайту** и страница «Новости» с фильтрами (по категориям и датам).
- **SEO.** Описания страниц, карта сайта `sitemap.xml`, микроразметка организации и учебных программ.
- **Резервные копии.** Раз в неделю сохранять копию репозитория и загруженных файлов (`wp-content/uploads`)
  в отдельное место.
